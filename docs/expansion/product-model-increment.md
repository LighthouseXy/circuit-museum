# 产品资料库与博物馆：内容模型增量交接

本轮新增定位已合并到原研究和正文工作。网站有两个共用内容的核心：广泛的产品资料库（工作名），以及精选馆藏和产品编年史。栏目正式名称待用户确定。长期目标是从电子产品发展早期至今持续覆盖优秀或获可靠好评的产品；本阶段至少150件实际导入且可浏览，是阶段验收数量，不代表已经全面收录。

## 共用一个型号实体

沿用唯一slug及来源登记，不为资料库、馆藏、编年史另建重复型号。配色、容量与没有独立使用结构变化的销售组合不重复计数；真正不同代际、地区硬件或关键版本在实体的版本范围中明确，必要时才另立型号。

资料库是产品内容入口；馆藏成员资格是可选的策展关系；编年史的阶段引用同一slug。原40件馆藏继续保留。216件既有正式选择不重新研究或重开整轮筛选，现有页面方案的位置可作为候选引用保留，但不把216件一律宣布为最终馆藏。没有强烈历史影响的产品也可以作为资料库候选。一条可靠、具体、正面的媒体原评即可支持候选判断，不要求多个媒体共识或大奖。

品牌资料与博物馆身份档案能够核实事实，不能冒充独立正面评价。尚无可靠原评的既有记录标为评价待补，不写“媒体一致认可”或排名。产品资料是否完整、是否已导入、是否具备原评、是否列入馆藏各自登记，不能用其中一个状态代替另外三个。

## 保留旧稿，按证据增加字段

原14份完整稿保留，后续完整稿延续五节正文、段落引用、具体年份地区版本、关联和文字回退。五节中的significance作为可选策展解释，不作为所有产品进入资料库的门槛。兼容旧数据的增量包括：

- `specifications`：配置规格条目，含label、value、unit（需要时）、versionScope、sourceIds、verificationStatus。不同类别采用对应规格，不强迫电饭锅填写CPU。身份年份不能冒充性能配置；缺少的关键规格列入unverifiedFields。
- `functionsAndScenarios`：明确能力及对应任务，引用已核事实或段落来源。厂商宣传、原评作者体验和策展解释分别标示，不用营销形容词填空。
- `designCharacteristics`：外形、结构、控制和材料等有来源的特点；无法由来源证明的舒适、耐用或效率不作事实。
- `mediaOpinions`：沿既有署名、文章日期、精确型号、原文URL、肯定、保留意见、评测条件、商业披露、读取深度及sourceId。原评没有列缺点时不补造；未读性能分页不记成已核测试条件。
- `lifecycleEvents`：同一型号的可核事件，使用下方日期规则。
- `lifecycleStatus`：制造结束、销售结束、支持结束及当前可获得性分别登记；未知是未核，不是已结束或仍在售。
- `museumMembership`、`chronicleReferences`：引用同一产品的策展关系，避免重复实体。
- `mediaAssets`：图片、视频来源与许可登记；现有heroMediaId/videoIds继续兼容。没有可用许可时使用文字回退，不用图片URL等同于转载许可。

每类字段允许部分完成。正文完整不意味着所有配置、评价与整个历程都已核齐。总包中的contentCoverage逐项说明，不以空数组暗示没有发生过质量问题或后续更新。

## 产品历程：事件各有时间与范围

一个事件含eventType、date、datePrecision、description、regionVersion、sourceIds、temporalPerspective、verificationStatus。日期以来源精度保存，可以是年、月、日、约略区间或原文标签；不为排序补造月日。发布时间与事件发生时间可以不同，另存sourcePublishedOn（来源确实给出时）。

事件类型可记录公告、预订、计划上市、实际销售开始、生产开始、版本或功能更新、重要评测、来源支持的市场反应、质量问题、召回、争议、生态或用途变化、生产结束、销售结束、支持结束及后来的回顾。只记录确有证据的节点，不强迫每个产品填写每一类。

`temporalPerspective`区分当时资料、当时评价、后来回顾和策展解释。产品线事件不能无条件归给原代型号；软件更新后的功能不能回填首发配置；后代发布也不代表原代同时结束。跨地区供应可有多个事件，但不多算实体。仍在售或支持的产品不虚构结束；没有当前证据的产品写当前状态未核，不作实时购买承诺。

本次明确纠正K380日本公告的“発売予定日”：2015-11-05是计划销售日，不是该来源已证实的实际首售。ScanSnap所读PDF是2001年11月第四版；版次表中的8月第二版不代表当前文件就是第二版。正文批包与来源范围已经按此修正。
